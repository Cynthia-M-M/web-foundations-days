# Course Reflection

Looking back at the Web Development Foundations course, the most difficult concept for me to grasp was the transition from building isolated frontend interfaces to understanding distributed state in System Design—specifically, how to manage database connections and caching mechanisms like Redis under high traffic. Initially, the idea of data existing in multiple places simultaneously (an in-memory cache, a primary database, and asynchronous read replicas) felt chaotic and prone to race conditions. I overcame this by mentally mapping out the "Cache-Aside Pattern" step-by-step on paper and realizing that the database remains the ultimate authoritative source of truth, while the cache is simply a temporary, highly optimized reflection of that truth.

Regarding my QuickNotes capstone project, the peer feedback I received was incredibly helpful. One reviewer pointed out that my error handling for failed `fetch()` requests was too rigid, leaving the user confused if the backend timed out or encountered network disconnects. Based on this, I would improve the capstone by implementing graceful degradation—specifically, displaying user-friendly toast notifications for network errors and utilizing `localStorage` as an offline sync queue so users never lose unsaved notes when their internet connection drops.

Moving forward, I want to dive deeper into DevOps and backend infrastructure. I plan to learn how to containerize full-stack applications using Docker and orchestrate them with Kubernetes, so I can deploy the horizontally scaled architectures we designed in Day 8 to a real cloud environment like AWS.
